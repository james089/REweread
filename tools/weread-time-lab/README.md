# 电脑端独立时长测试

不连接 reMarkable，不读取插件或独立 App 的登录和用户数据。需要 Node.js 22 以上及 Lua 5.3 以上。

```sh
cd tools/weread-time-lab
npm ci --ignore-scripts
bash setup-protocol.sh
npm start
```

浏览器打开 <http://127.0.0.1:8787>，点击「显示登录二维码」，用微信扫码确认。
二维码由本机生成，不调用第三方二维码服务。未点击「开始测试」前不发送阅读入场或时长。

登录后读取书架并选择测试书。若网站书架格式变化导致无法读取，可手动填写真实 bookId。
选择 30 秒、2 分钟、10 分钟或 1 小时，确认写入提示后开始。不要同时在其他客户端阅读；
保持电脑唤醒。进入阅读会更新最近阅读，时长写入会影响同一账号的云端记录。

每轮执行：

1. 从网页 reader.progress.book 读取保存位置、总时长及当前请求状态。
2. 持久化请求意图，发送一次无 rt 的进入阅读请求，检查业务回执。
3. 从回执成功开始用单调时钟实际等待所选时长；明显事件循环停顿则中止。
4. 再读保存位置；章节、偏移、百分比或摘要变化则停止，不覆盖其他客户端位置。
5. 持久化请求意图，发送一次带实际等待秒数 rt 的阅读请求，保留当前保存位置。
6. 立即、约 15 秒及 45 秒后只读回查总时长，分别显示业务回执与观测到的累计差额。

不补传历史，不自动重试写请求，不因回读未增加而重发，不恢复中断测试。请求结果不明时
持久化记录并停止。重新启动工具不会重放旧记录。「停止等待」不能撤销已发出的请求。
关闭浏览器不停止服务或测试；使用页面停止按钮，或在启动终端按 Ctrl+C。

## 私有数据

macOS 默认目录：`~/Library/Application Support/REweread-TimeLab/`，目录 0700、文件 0600。
`session.json` 保存独立 Cookie；`run-*.json` 保存私有测试记录（含书籍 ID 和总时长）。
两者均在仓库之外。页面状态、日志及错误不输出 Cookie、token 或二维码 UID。
当前版本不支持需要额外短信 OTP 的账号验证。扫码失效时在页面重新生成。

只监听 127.0.0.1:8787，拒绝异常 Host 和跨源写请求，不提供凭据导出接口。
Web 协议并非官方稳定契约；总时长回读差额不代表准确的每日归属，也不能排除其他客户端
或统计延迟影响。该工具复现 Web 入场/等待/上报生命周期，不验证设备计时、睡眠事件或 Lua 封装。

## 本地测试

```sh
npm test
```

测试使用合成账号、伪时钟和伪 HTTP，不向真实账号上传。真实入场/时长请求直接调用
本机独立获取的插件同源 Lua `make_enter_read_payload` / `make_read_payload`；回执调用本项目
`read_sync_protocol.lua`。Node 仅提供登录、HTTP、单调计时、私有存储以及 MD5/SHA256 原语。
外部 Lua 模块固定提交及校验和，留在忽略的 downloads/time-lab-runtime；不打包进 Git。
未连接设备核对其当前外部依赖哈希，不能声称与设备运行时逐字节一致。

普通页面测试仍等待和提交相同时长。操作员专用的 `/api/experiment-enter20-report60` 仅用于
用户明确授权的等待20秒/上报60秒对照实验；持久化意图后只允许启动一次，不自动重试。
该实验不会修改设备上的计时账本，不能据此重放任何历史回执。
