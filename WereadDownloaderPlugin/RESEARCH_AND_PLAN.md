# 研究与执行计划

研究日期：2026-10-21。

## 结论与证据边界

技术路线有条件可行。书架、封面和 EPUB 打包在现有项目已有实现；设备原生扩展和原生导入有公开先例。但当前不能认定整个原生插件已经具备安全执行条件：目标固件、原生扩展构建接口、导入完成后的文档身份关联仍需验证。

用户已确认：入口放在系统主界面左侧栏 AppLoad 正下方，点击直接打开插件页面，无需进入设置；首次进入独立扫码登录，成功后显示书库，登录有效时再次进入直接显示书库。安装后不依赖电脑持续在线。只保证本插件后续导入书籍的来源识别与去重，不兼容安装前已存在的书籍。

### 本地已核实

- `apps/weread-move/lib/shelf_service.lua`、`shelf_cache.lua` 与 `tools/refresh-shelf.lua` 提供书架获取、缓存和封面流程。`native_shelf.lua` 名称虽有 native，但它是项目自己的缓存视图，不是 Xochitl 系统书库接口。
- `download_manager.lua` 的 `start_full_download` / `step_full_download` / `finish_full_download` 支持分章下载、续传和 EPUB 打包；实际打包调用运行时 `lib.content` 的 `save_book_epub`，不是官方整本 EPUB 下载接口。
- `epub_compatibility.lua` 修复 XHTML 实体和重复资源冲突；新项目需要保留等价验证。
- `tools/redownload-book.lua` 以最终 `result state=full|partial|opening path=...` 表示本次产物；进程返回成功或文件存在都不足以证明完整。新桥接应返回结构化结果且不透传原始日志。
- 现有下载器允许 partial EPUB。新插件只接受本次完整完成、无缺章且文件通过检查的 EPUB；试读权限与目录完整性需要额外验证，不能承诺所有书都可下载。
- 当前下载和登录依赖用户另行安装的 KOReader / weread.koplugin。后者权利链未解决，不能打包复制到新项目或发布归档中。

### 外部已核实

1. [rmtool 仓库](https://github.com/pretenderlu/rmtool)：阅读增强是按设备和固件精确匹配的扩展；不是已证实存在的通用第三方插件 SDK。其 GPL-3.0 与当前项目 MIT 边界需要分清。
2. [rmtool QR upload 设计与验证记录](https://github.com/pretenderlu/rmtool/blob/main/qr-upload/README.md)：提供设备原生页面、Qt 桥接、原生导入的先例。只据此确认路线存在，不推断本设备版本兼容，也不把上游的实测当本项目实测。
3. [原生上传按钮项目](https://github.com/rM-self-serve/webinterface-upload-button)：提供系统 Web 导入的历史参考；其本身不是当前 Move 兼容性证明。

初次研究时部分源码未能获取；后续已通过 GitHub 连接器获取并审查相关原生桥接和导入控制，固定上游 commit 和已知接口，见 `native/INTEGRATION.md`。实际设备固件和资源回放仍未验证，不能根据上游源码推断本机兼容。

## 用户可见行为

- 每行：封面、书名、作者、导入状态、选择框和“导入”按钮。提供刷新、仅显示未导入、导入所选、取消等待项。
- 状态：未导入 → 排队 → 下载中 → 校验中 → 导入中 → 待系统确认 → 已导入；另有失败、取消、状态待核实。
- 已导入不可选择或再次导入；排队/处理中禁止重复提交。同一本在真正提交系统导入前再查一次去重。
- 书籍权限不足、缺章、EPUB 无效、空间不足时明确失败，不把不完整产物导入系统。
- 系统已接受上传但尚未确认书库记录时，显示“待系统确认”；网络超时等不确定结果禁止自动重传，先对账。
- 从第一阶段就使用插件独立扫码登录和独立凭据存储，不复用现有阅读器的登录会话。UI、IPC 和日志不得携带 Cookie/token；账号切换清空内存模型并使用分账号缓存。

## 架构

| 层 | 职责 |
| --- | --- |
| 原生入口与 QML 页面 | 设备内封面列表、选择、状态展示；按精确固件适配 |
| Qt 桥接 | 有界异步 IPC、页面生命周期、队列控制；不阻塞 Xochitl 主线程 |
| 独立 worker | 串行下载、校验、导入、恢复，不继承 XOVI preload |
| WeRead adapter | 调用现有 helper 能力；新结构化协议，不解析不受控日志作为凭据 |
| NativeLibrary adapter | 读取系统文档身份、导入和对账；不手写系统 `.metadata/.content` |
| 私有状态库 | bookId、账号作用域、产物摘要、系统文档 UUID 和任务事务记录 |

程序和构建源码放本目录。私有运行数据使用独立目录，目录权限 0700、敏感文件 0600；不写到仓库，不移动或删除现有客户端数据。无常驻监听端口，退出/锁屏后的下载暂停策略必须实测。

## 系统书库去重

需要覆盖系统书库所有目录，而导入目的地是根目录。已移入文件夹的书仍算存在；已移入回收站的记录独立处理。

1. 每个由插件生成并导入的 EPUB 必须在 OPF 元数据内写入稳定来源标识，例如 `urn:weread:book:<bookId>`；保留原有出版标识，不用书名代替来源 ID。写入后重新读取校验，缺失或不一致则禁止导入。
2. 私有事务记录同时保存来源 bookId、账号作用域、EPUB 摘要与系统文档 UUID。书籍身份使用 bookId，账号作用域用于隔离缓存和任务，不将同一本书变成不同身份。
3. 确认系统导入后能从原始 EPUB 读取来源标识，以便本地映射丢失或崩溃时重建关联。此能力是设备验收门槛，未验证前不能承诺已实现可靠去重。
4. 只索引带有本插件来源标识的文档，以及本插件已确认 UUID 的文档。不匹配历史同名书，不提供历史书手动关联，也不因同名而禁用导入。
5. 提交前持久化任务意图并再次按来源 ID 对账；系统确认后原子保存 UUID。超时或崩溃先恢复对账，不盲目重传。
6. UUID 记录不能代替实时书库检查；改名、移动后仍禁止重复导入。删除/回收站的状态需明确显示，恢复或重新导入策略在实现时单独定义。

## 分阶段执行与门槛

### 0. 适配研究闭环（当前下一步）

- 获取并固定 rmtool 相关源码 commit；审查原生页面/桥接/导入控制实现和许可证，第三方源码放仓库外。
- 只读确认目标 Move 的精确系统版本、架构、Xochitl 指纹、XOVI 版本与现有扩展；只输出兼容性结果，不输出用户书库或配置内容。
- 证明可以枚举有效原生文档、区分根目录/文件夹/回收站，并可靠关联一次导入结果。
- 明确原生入口采用的 SDK、Qt ABI、固件资源与构建方式。未知固件拒绝安装。
- 退出门槛：形成可实现的适配契约；若不能稳定观察导入结果，调整确认机制后才能继续写导入代码。

### 1. 核心与模拟验证

- 编写分账号状态、去重、串行任务队列和事务恢复模块；先用合成书库/EPUB 测试。
- 覆盖双击/批量重复、同名异书不误判、本插件已有书、移动/删除/回收站、并发外部导入、崩溃窗口、上传结果不确定、损坏状态库。
- 使用假 adapter 完整跑通选择 → 下载 → 校验 → 导入 → 确认，不访问用户账号。

### 2. 下载与 EPUB

- 受控复用现有章节下载和打包能力，明确运行时依赖，不复制未授权上游。
- 完整性门禁：目录/成功章节一致、无失败、非试读、路径限定、EPUB ZIP/container/manifest/spine/资源引用校验、磁盘空间检查。
- IPC 不传任意命令或文件路径。取消保留安全续传点；失败不暴露原始 HTTP/helper 输出。

### 3. 原生页面与导入

- 完成独立入口、封面懒加载、单书/多选导入、错误重试、本插件已导入标记。
- 原生 HTTP importer 提交 EPUB，让系统生成自己的文档与转换结果。明确验证根目录语义，不能假定默认行为。
- 复用已启用的系统导入服务；如需临时启用则保存原设置并恢复。不能通过反复重启 Xochitl 达到刷新书库效果。

### 4. 构建、设备验收与交付

- 仓库安全检查、`node tests/run-all.mjs`、shell 语法检查；新项目行为测试；适用的官方 chiappa SDK 构建和原生扩展专用构建。
- 部署前列明文件、固件门禁、备份与回退方案。需要改系统、重启或改变 Xochitl 服务时先解释具体动作。
- 先合成 EPUB 验证原生根目录出现且正文能读，再做用户选定书籍的完整下载导入。
- 验证重复导入禁止、重启恢复、暂停/断网/空间不足、移动/删除后状态、原生标注和原有插件共存。
- 卸载只移除插件文件，保留导入书籍和账号数据。用户数据删除必须独立明确授权。
- 记录本地与设备实测的区别；公开分发继续受根项目 release checklist 和第三方权利链约束。
