# 官方客户端接口与同步能力补齐

日期：2026-10-12。源码基线：GitHub main 0271ab2，版本 2.0.0。
官方样本：腾讯 CDN RemarkableWeRead 1.0.0 通用包。仅静态分析公开程序，不读取账号凭据，不复制官方源码。

## 通道证据

官方二进制含 weread.qq.com 的 Origin/Referer、网页 Cookie 字段名和网页会话续期路径，但字符串不能证明所有请求都走网页协议。后续函数级分析确认原生请求注入 `vid`、`accessToken` 请求头；其基础 URL 和服务端契约仍未完整确认，没有证据证明存在可供本项目直接使用的免校验设备通道。

| 能力 | 官方可见端点/数据结构 | 本项目缺口 |
| --- | --- | --- |
| 书架 | /shelf/sync、/shelf/syncbook；增量同步表 | 现有刷新/缓存，不具备同等增量状态 |
| 进度 | /book/getProgress、/book/read；章节、偏移、时间戳 | 当前 helper 上报章节位置为零；只按百分比拉取；本地位置优先，无时间戳冲突解决 |
| 时长 | /book/read；readingTime、reading_time | 缺可靠离线 outbox、服务端幂等性确认与账号隔离 |
| 离线 | /book/chapterInfos、/book/chapterdownload；版本、章节批次与内容完成记录 | 本项目逐章读取后封装 EPUB，缺可信续传清单、失败章节重试与版本失效 |
| 笔记 | ink_strokes 本地 SQLite | 官方手写上传未找到证据；本项目云笔记读取与本机笔记保存分离，没有写回 |

端点名字只证明存在相关调用线索，不构成请求字段、签名算法、授权或幂等性契约。官方章节下载包含加密包相关字段；本轮未实现其解密或认证替换。

### REA 函数级交叉核验

2026-10-12 使用 [morluto/rea](https://github.com/morluto/rea) 的 npm 6.4.0、Ghidra 12.1.4 和 JDK 21，对官方 1.0.0 可执行文件做只读分析。分析样本 SHA-256：`5a117d08c8503bad49b65a54357cdc1698b0ae3e52550d704fe9c6262f061ac7`。引擎、样本与分析数据库均在仓库外，未接触用户登录态。

- `/book/read` 字符串地址为 `0x3dab78`；引用位于 `0x173784`，所在函数入口为 `0x173700`。
- 函数级反编译确认它设置 `application/json`，组装 `bookId`、`chapterUid`、`chapterIdx`、`chapterOffset`、`progress`、`readingTime` 六个字段，然后经序列化辅助函数调用 Qt 的网络 POST。
- 请求初始化 `0x16cc10` 设置 JSON Accept/Content-Type，并根据 URL 设置网页 Origin/Referer；`0x16b640` 仅做 QVariantMap → QJsonObject → compact JSON，没有额外签名或加密包装。
- 会话注入 `0x16c8c0` 使用 `vid` 和 `accessToken` 请求头，不是 Bearer。`vid` 常量地址 `0x3da348` 映射文件偏移 `0x2da348`，已直接核验。URL 判定 `0x17dad0` 要求 HTTPS、规范化主机等于 `qq.com` 或以 `.qq.com` 结尾。本项目不照搬这一宽泛凭据发送范围，也不读取官方应用的凭据。
- 当前插件读取部分数据使用 `https://i.weread.qq.com/api/agent/gateway` 的 Bearer API Key；网页阅读写入使用 `/web/book/read` 的签名载荷。这两者与上述 native JSON 接口不是同一个协议，不可混用。
- `/book/read` 的基础 URL 来自客户端字段；该函数仅透传整数位置和时长，尚不能证明时长单位/幂等语义或 chapterOffset 编码。不能直接把字段名移植为可用协议。
- Ghidra 本样本 image base 比 ELF VA 多 `0x100000`，文件偏移还需依据 PT_LOAD 映射；用 `strings` 偏移直接查 xref 会得到误导性空结果。间接引用的空 callers 也不能理解为“无人调用”。
- 继续追踪发现 `0x181540` 写的是 `books.read_update_time`，缺省使用 `currentSecsSinceEpoch()`；章节打开日志中的“local read time”指最近阅读时间戳，不是累计 `readingTime`。远端进度解析回调 `0x1a3ee0` 对 `chapterOffset`、`readingTime` 直接 `toInt(0)`，本地保存也没有换算；另外的 `update_time` 才用毫秒时间戳。这些证据不足以确定服务端原始整数的单位。

REA 在这里确有帮助：它能够把接口字符串连接到具体函数、伪代码与调用证据；它不是原始源码恢复器，也不会自动解决授权或跨端坐标语义。

## 本轮已补

- 阅读计时不再把 Date.now() 存入 QML 32 位 int（会溢出）。以观察到的前台阅读间隔累计毫秒；休眠、后台、超过 5 秒的定时器空档与时钟倒退均不整段计入。
- 按账号 SHA-256 命名空间持久保存每本书的未发送时长，每 10 秒及离开前台/退出时保存。提交前原子地转为“结果待确认”；成功才清除。失败或响应丢失不会自动重复补报这部分时长，避免虚增；新产生的时长独立保留。
- 同步进程必须输出完整 state=done 且正常退出才报告成功；处理输出分片、启动失败、25 秒超时和 state=error。
- 部分章节失败生成 partial.epub，并显示部分可读；不再把新生成残缺文件称为 full.epub。旧版本已误命名的文件不能仅凭文件名追溯修复。
- 排队任务保留 openingChapter，重启后不把“开头章节”任务误变成整本任务。
- 笔记按钮明确为“拉取云端笔记”，不暗示本地手写已上传。
- 个人云笔记按账号隔离缓存，先显示本地已有内容再刷新；只有完整成功的响应覆盖缓存，超时/失败不写入半截结果。登出或切换账号立即清理内存中的旧账号笔记。
- 手动拉取进度优先以远端章节 UID 和摘要在本地正文中唯一定位；短摘要、歧义或缺失字段退回百分比。自动打开仍优先本机进度。上传保留百分比兼容路径，不把本机 UTF-16 偏移冒充远端章节偏移。
- 每本书保存逐章续传清单：目录指纹、账号范围、正文/图片大小与校验。中断后复用校验通过的章节，损坏/缺失章节重新获取；失败章节最多重试两次，目录或账号变化使旧清单失效。
- 上游阅读载荷对摘要使用 20 字节截断；现在先在合法 UTF-8 边界内截取，中文和 emoji 不再被截成非法编码。实际安装的上游实现已确认 `rt=0` 原样保留，不会变成默认时长。
- HTTP 2xx 不再等于业务写入成功。明确失败或未识别的响应均保留时长待确认；stderr 不能伪装为 helper 完成协议。失败回调立即更新账本/UI，成功落盘失败也不提前清除内存账目。
- 详细云端位置只接受同一个 `progress.book` 记录的完整字段，不再混拼当前显示章节与另一条进度记录。自检模式禁用阅读计时和进度上传。
- 离线时长累计超过 24 小时不再归零，采用一年范围的饱和上限，避免整数秒溢出。
- 新增“我的 → 阅读统计”：今日、本月、累计、本月阅读天数与本数、近 7 天明细。按北京时间从实际采样逐日记录，跨午夜拆分；独立账号 statistics.json、原子保存及书籍标识哈希化，不从旧待同步时长猜测历史，不因提交成功清零。加载书籍期间暂停采样，账号 generation 防止旧采样进入新账号。
- 兼容旧会话中的非 UTF-8 Cookie 字节：Qt 仅在 `IllegalUTF8String` 时在内存重试解析，且回退身份必须是非空 ASCII 数字；阅读账本和笔记缓存共用此检查，不修改登录态文件。其他 JSON 语法错误继续拒绝。

## 阅读排版与界面

- 参考官方字体面板的独立选择方式，新增三列字体预览网格，显示已安装/不可用状态，笔点击使用卡片实际坐标；保留字号、行距、段距与页边距设置。
- 图片按 XHTML 中的真实正文位置进入块级页流，保留重复使用的图片资产，不再按章节长度比例猜位置。分页停在下一张图片之前，章末图片不再切走最后一个字；全书尾图另建展示页。
- 图片按宽高比显示，同锚点组共用安全高度预算，避免覆盖正文和页脚。图注仍保留在原始正文流里，alt/title 元数据不插入正文，也不参与批注坐标补偿。
- 这不是完整 EPUB/CSS 引擎：浮动图文、复杂表格未实现；大量同锚图片会整体缩小而非拆为多页，不能保证极端图组可读。图片锚点改动不改变原正文及历史 textOffset。
- 排版自检扩为 13 种字体选项 × 4 种行距，并抽查正文位置。自检用独立临时偏好设置，不改变用户字体选择；显式开启时只复制已有 CPU 帧缓冲，截图保存在设备 `/tmp`、权限 0600，不进入仓库。

## 尚未完成及下一步

1. 历史书架/整本文件/本地进度仍有共享目录，未进行破坏性迁移；新增时长和个人笔记已隔离，章节续传也验证账号。不能宣称应用所有历史数据均已账号隔离。
2. 服务端没有已核实的幂等键，因此结果不明的时长保留待确认而不自动重放，可能少计但避免重复记账。没有添加周期自动上报。前台静置仍计时，不能判断人是否实际阅读。
3. 精确章节进度：将本地文本偏移映射到真实远端 chapterUid/chapterOffset，取得远端更新时间后处理多设备冲突；不要凭章节序号或百分比猜测。
4. 笔记双向同步：先将已读取的个人划线映射正文，再依据验证过的创建/更新/删除协议实现明确的上传动作。自由笔迹与文字笔记需区分，不能自动把手写发布为公开想法。
5. 离线下载剩余限制：尚无磁盘容量预检；不同 URL 的同名图片仍沿用旧 basename 目录结构，校验能阻止错误复用但不能消除命名冲突。服务端未提供版本字段时，目录不变的正文更新也不能仅凭目录指纹发现。

## 验证边界

新增行为测试覆盖 JS 阅读计时、Qt 阅读账本的持久化/切号/不重复补报、Qt 笔记缓存账号切换与漏行拒绝、进度和笔记中文 UTF-8 跨输出块，以及真实 Lua 执行的中断恢复、损坏缓存、目录与账号变化、失败重试和 partial 产物。下载测试也已在设备自带 LuaJIT 上使用隔离假数据通过。同步进程、个人笔记缓存及下载状态另有源码契约验证；这些不是线上服务验收。未向真实账号发送虚构测试时长或笔记。构建结果与真机验证应分别记录，不能以静态测试替代实机验收。

本机 QtCore 行为测试入口为 `tests/run-sync-smoke.sh`，设置 `QT_PREFIX`、`QT_MAJOR`（5 或 6）以及需要时的 `QT_INCLUDE`、`MOC` 后运行。测试使用临时目录和虚构账号，不连接微信读书。四组覆盖：时长账本、进度输出协议、个人笔记缓存、下载结果协议。

已有兼容安装可使用 `MOVE_HOST=... bash scripts/upgrade-weread-qt-files.sh` 更新应用文件。它保留已安装字体、AppLoad 和用户数据，校验新二进制 SHA-256，保留带时间戳的旧应用备份；不重挂载系统、不重装 XOVI，也不会自动启动或宣称真机验收通过。首次安装仍使用原安装流程。
