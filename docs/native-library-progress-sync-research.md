# 原生书库 → 微信读书阅读位置：调研与执行方案

日期：2026-10-22。研究阶段，没有新增同步功能，没有向真实账号写入进度或时长。

## 结论

可分三段实现：原生 UUID 关联微信读书 bookId → 获取系统阅读位置 → 转换为微信读书位置并上报。第一段已有可靠基础，第三段有可复用 helper；第二段的精确位置获取和跨排版映射仍需在当前 Move 固件上验证。因此不能把“可以读取页码”直接等同于“手机能续读到同一句”。

## 已有证据

- `WereadDownloaderPlugin/src/import_registry.*` 保存真实 bookId 与原生文档 UUID；导入 EPUB 写入来源标识，重扫可校验关联。无需书名匹配。只处理来源已验证、当前账号拥有、仍在系统书库中的文档，历史无来源标识书籍不纳入。
- `apps/weread-move/tools/sync-progress.lua` 已实现网页会话读取、阅读载荷构造和 `client:report_read`；`lib/read_sync_protocol.lua` 检查业务成功，不能将 HTTP 2xx 当作上报成功。精确参数为 chapterUid、chapterIdx、chapterOffset；兼容路径只发百分比，章节字段为零，不能声称精确定位。
- 该 helper 默认使用独立 App 的配置与会话路径。插件不能直接启动原脚本就当作复用完成：必须将其逻辑接入插件独立 Config/context、账号隔离和会话续期流程，禁止借用独立 App 凭据。
- `docs/official-client-sync-gap.md` 已记录章节偏移单位及多设备冲突尚未充分验证；本机文本 UTF-16 偏移不能直接冒充云端偏移。原生 `/book/read` 静态分析不能代替线上契约验证。
- 外部项目的结构说明列出 `.content` 的 `lastOpenedPage`（从零开始）及原生 EPUB/PDF 文件；这是社区协议资料，不能证明当前固件一定保留同样字段或更新时机。
  - https://github.com/ciesko/rmSync/blob/main/README-CONCEPTS.md
  - https://github.com/psanford/remarkablecloud
- 本次尝试通过 USB 只读统计已导入文档的 `.content` 字段类型，连接超时，没有取得样本。尚未证实当前固件的字段结构、页数口径、阅读退出后落盘时机或 EPUB 定位信息。没有为研究重启系统、唤醒轮询或输出用户书名/文档标识。

## 获取位置的优先路线

1. 在当前固件只读检查已验证来源文档的 `.content` 及关联位置文件：是否含 EPUB CFI、spine/href、字符位置，或只有 lastOpenedPage；同时检查页列表、原始页与显示页映射、生成 PDF 是否存在。对外仅输出字段类型及判定结果，不保存真实用户文件到仓库。
2. 用一份合成 EPUB 验证：打开正文、翻页、退出、改变字号重新分页，比较位置字段如何变化；包含封面、目录、图文和非连续章节 UID。检查添加/删除/隐藏页面后 lastOpenedPage 的对应关系。
3. 若有稳定 EPUB 锚点，沿 EPUB spine/href → 原 chapterUid → 正文锚点进行映射。需核实章节缓存是否已经保留准确 UID；若没有，在下载打包时额外保存私有映射，不能假设 spine 序号就是 UID。封面补齐新增的首个 spine 页必须排除在章节编号外。
4. 若只有页码：先研究系统生成 PDF 的当前页文本/文本层，使用唯一正文片段匹配原章节，并验证原始页映射。当前插件没有已验证的 PDF 文本提取方案；缺失文本层、纯图片、重复段落或多处匹配时应判定无法精确定位。
5. `lastOpenedPage / pageCount` 只适合作为标注“估算”的显示候选，还需明确零基/尾页、页映射和排版版本。不能直接按该百分比覆盖云位置：封面、目录、插图和不同章节页密度都会造成误差。

## 上报与冲突策略

- 初版提供显式“同步阅读位置”，先显示系统位置、云端位置及定位可信度；默认不做后台自动写入。
- 使用插件当前账号的独立登录态；读云进度确认账号/bookId，禁止混用注册表中另一账号的导入记录。
- 读云端同一进度记录中的章节、偏移、摘要及可信更新时间。文件 mtime 可能来自其他文档操作，不等于阅读时间；拿不到可信时间或两端都变化时要求用户选择，不能自动回退手机上的新进度，也不能假定百分比更大总是正确。
- 先验证远端偏移坐标（字节、字符、UTF-16 等），通过正常读过的位置小规模对照，不发送虚构位置。时间字段明确传零；本需求同步位置，不从文件时间推算阅读时长。
- 按账号/bookId 保存待发送位置、源排版/文件指纹与最近确认位置。仅业务明确成功且读回位置相符才显示“已同步”；响应丢失记“待核对”，先读回，避免盲目重试。位置与时长重试语义不能混用。
- 书籍删除、账号切换、映射失败、重排未完成或来源冲突时停止该条同步。全过程不修改系统书库的阅读文件。

## 建议执行顺序与验收

1. 只读原型：插件列出每本书的系统位置、可用字段与映射状态，不访问写接口。
2. 合成文档验证映射：正文章节、封面/目录、插图、字号重排及页面编辑矩阵；证明同一正文位置仍映射到同一章节。
3. 接入独立账号的云进度读取，验证过期续期、离线、切号和两端冲突。
4. 接入手动单本同步，复用现有载荷与确认逻辑；先验明真实位置，再做手机端续读验收。失败明确反馈，不显示虚假成功。
5. 手动同步稳定后再讨论离开原生阅读器或进入插件时自动同步。需额外评估观察事件/文件变更去抖和电量，不新增高频常驻轮询。

当前适合开始步骤 1–2；精确同步可行性需这两步验证后才能确认。本轮没有部署新的阅读同步代码。
