# 原生书库 → 微信读书阅读位置：调研与执行方案

日期：2026-10-22。研究阶段，没有新增同步功能，没有向真实账号写入进度或时长。

## 结论

可分三段实现：原生 UUID 关联微信读书 bookId → 获取系统阅读位置 → 转换为微信读书位置并上报。第一段已有可靠基础，第三段有可复用 helper；第二段的精确位置获取和跨排版映射仍需在当前 Move 固件上验证。因此不能把“可以读取页码”直接等同于“手机能续读到同一句”。

## 已有证据

- `WereadDownloaderPlugin/src/import_registry.*` 保存真实 bookId 与原生文档 UUID；导入 EPUB 写入来源标识，重扫可校验关联。无需书名匹配。只处理来源已验证、当前账号拥有、仍在系统书库中的文档，历史无来源标识书籍不纳入。
- `apps/weread-move/tools/sync-progress.lua` 已实现网页会话读取、阅读载荷构造和 `client:report_read`；`lib/read_sync_protocol.lua` 检查业务成功，不能将 HTTP 2xx 当作上报成功。精确参数为 chapterUid、chapterIdx、chapterOffset；兼容路径只发百分比，章节字段为零，不能声称精确定位。
- 该 helper 默认使用独立 App 的配置与会话路径。插件不能直接启动原脚本就当作复用完成：必须将其逻辑接入插件独立 Config/context、账号隔离和会话续期流程，禁止借用独立 App 凭据。
- `docs/official-client-sync-gap.md` 已记录章节偏移单位及多设备冲突尚未充分验证；本机文本 UTF-16 偏移不能直接冒充云端偏移。原生 `/book/read` 静态分析不能代替线上契约验证。
- 外部项目的结构说明列出 `.content` 的 `lastOpenedPage`（从零开始）及原生 EPUB/PDF 文件；这是社区协议资料，不能证明当前固件一定保留同样字段或更新时机。
  - https://github.com/ciesko/rmSync/blob/main/README-CONCEPTS.md
  - https://github.com/psanford/remarkablecloud
- 本次尝试通过 USB 只读统计已导入文档的 `.content` 字段类型，连接超时，没有取得样本。尚未证实当前固件的字段结构、页数口径、阅读退出后落盘时机或 EPUB 定位信息。没有为研究重启系统、唤醒轮询或输出用户书名/文档标识。

## 获取位置的优先路线

1. 在当前固件只读检查已验证来源文档的 `.content` 及关联位置文件：是否含 EPUB CFI、spine/href、字符位置，或只有 lastOpenedPage；同时检查页列表、原始页与显示页映射、生成 PDF 是否存在。对外仅输出字段类型及判定结果，不保存真实用户文件到仓库。
2. 用一份合成 EPUB 验证：打开正文、翻页、退出、改变字号重新分页，比较位置字段如何变化；包含封面、目录、图文和非连续章节 UID。检查添加/删除/隐藏页面后 lastOpenedPage 的对应关系。
3. 若有稳定 EPUB 锚点，沿 EPUB spine/href → 原 chapterUid → 正文锚点进行映射。需核实章节缓存是否已经保留准确 UID；若没有，在下载打包时额外保存私有映射，不能假设 spine 序号就是 UID。封面补齐新增的首个 spine 页必须排除在章节编号外。
4. 若只有页码：先研究系统生成 PDF 的当前页文本/文本层，使用唯一正文片段匹配原章节，并验证原始页映射。当前插件没有已验证的 PDF 文本提取方案；缺失文本层、纯图片、重复段落或多处匹配时应判定无法精确定位。
5. `lastOpenedPage / pageCount` 只适合作为标注“估算”的显示候选，还需明确零基/尾页、页映射和排版版本。不能直接按该百分比覆盖云位置：封面、目录、插图和不同章节页密度都会造成误差。

## 上报与冲突策略

- 初版提供显式“同步阅读位置”，先显示系统位置、云端位置及定位可信度；默认不做后台自动写入。
- 使用插件当前账号的独立登录态；读云进度确认账号/bookId，禁止混用注册表中另一账号的导入记录。
- 读云端同一进度记录中的章节、偏移、摘要及可信更新时间。文件 mtime 可能来自其他文档操作，不等于阅读时间；拿不到可信时间或两端都变化时要求用户选择，不能自动回退手机上的新进度，也不能假定百分比更大总是正确。
- 先验证远端偏移坐标（字节、字符、UTF-16 等），通过正常读过的位置小规模对照，不发送虚构位置。时间字段明确传零；本需求同步位置，不从文件时间推算阅读时长。
- 按账号/bookId 保存待发送位置、源排版/文件指纹与最近确认位置。仅业务明确成功且读回位置相符才显示“已同步”；响应丢失记“待核对”，先读回，避免盲目重试。位置与时长重试语义不能混用。
- 书籍删除、账号切换、映射失败、重排未完成或来源冲突时停止该条同步。全过程不修改系统书库的阅读文件。

## 建议执行顺序与验收

1. 只读原型：插件列出每本书的系统位置、可用字段与映射状态，不访问写接口。
2. 合成文档验证映射：正文章节、封面/目录、插图、字号重排及页面编辑矩阵；证明同一正文位置仍映射到同一章节。
3. 接入独立账号的云进度读取，验证过期续期、离线、切号和两端冲突。
4. 接入手动单本同步，复用现有载荷与确认逻辑；先验明真实位置，再做手机端续读验收。失败明确反馈，不显示虚假成功。
5. 手动同步稳定后再讨论离开原生阅读器或进入插件时自动同步。需额外评估观察事件/文件变更去抖和电量，不新增高频常驻轮询。

当前适合开始步骤 1–2；精确同步可行性需这两步验证后才能确认。本轮没有部署新的阅读同步代码。

## 2026-10-22 只读原型实测（后续会话）

USB 连接恢复，完成了真机读取与文本定位原型。此前“连接超时、未取得样本”的限制已被本节替代；云端偏移和手动同步仍未验证。

- 当前固件的 `lastOpenedPage`、`lastOpened` 在 `.metadata`，不在 `.content`；后者包含 `pages`、`pageCount`、`originalPageCount` 和 `redirectionPageMap`。抽样没有发现可直接使用的 CFI/章节字符坐标。
- 4 个注册表已导入文档均存在系统生成 PDF；页列表与重定向映射长度均等于 pageCount，映射均为恒等。仅 1 个文档有非零阅读位置和有效 lastOpened 时间。这个样本不能证明时间更新/落盘时机。
- 系统已有 `/usr/lib/libpdfium.so`。通过独立 LuaJIT 子进程调用公开 PDFium 文本接口成功，未安装新的 PDF 引擎或复制系统库；未在 Xochitl 进程中初始化 PDFium。
- 原型读取保存页码对应 PDF 页，4 个位置都在 PDF 页数范围内，其中 1 页有可提取文字，其余未取得文字（不能据此确定属于封面、图片还是文字层缺失）。
- 对有文字的位置，扫描其账号范围内的 106 个缓存章节，以正文连续 64 个 Unicode 字符为候选锚点，获得 1 个唯一章节匹配、0 个歧义。说明“系统 PDF 当前页 → 缓存章节”这条路线在本次样本可用；不是跨书籍/跨字号验收完成。

### 可复现代码与边界

- `WereadDownloaderPlugin/tools/probe-native-progress.lua`：独立只读诊断，不进入安装包、不新增插件按钮。只输出汇总计数，无书名、书籍/文档/账号标识、正文片段或凭据；没有网络调用或进度写入。最多约 25 秒/32 MiB 章节扫描，单章上限 2 MiB、每书最多 2000 章；文件 realpath 必须与目标一致。拒绝非恒等页映射、页数不一致、删除/回收站文档；匹配后再次检查 metadata/content 未变化。
- `tools/progress_probe_match.lua`：研究用 XHTML 去标签、基础实体/空白处理及多锚点匹配。拒绝短片段、跨章节/同章重复匹配。包含跳过少量页眉的候选，不支持完整 HTML/CSS 解析、断字恢复、OCR 或复杂排版。
- 本地测试：`lua WereadDownloaderPlugin/tests/progress_probe_test.lua`。相同测试已在设备 LuaJIT 通过，包含中文、emoji、实体、短片段、重复和重叠匹配。
- 最终原型在设备重跑仍是 4 个 PDF、1 个有文字页面、1 个唯一章节匹配、106 个章节扫描，cloudWrites=0。运行后已移除设备 `/tmp` 中本次诊断源文件。系统界面未重启，现有插件未升级，用户内容未复制离开设备。

### 下一步最小实现

先将该能力变成插件的只读“系统阅读位置”预览：没有打开记录或只有封面位置时显示“暂无正文位置”，匹配失败显示“暂不能定位”。缓存章节键只能证明本地候选身份，接下来仍须用原目录核对真实 chapterUid/chapterIdx、验证 chapterOffset 单位；归一化 XHTML 字节位置不可上传。原型目前只检查章节文件大小与清单一致，正式同步还必须复用下载清单 checksum 与目录指纹校验，并复验 EPUB 来源及当前登录账号。

随后做合成 EPUB 在两个字号下的正文定位和退出落盘测试，再接插件独立会话读取云端同本进度，最后才开放用户明确触发的单本上报。此次没有发送任何位置或阅读时长，也没有宣称精确手机续读已实现。

## 2026-10-22 原始章节坐标与云端只读对照

后续验证已完成此前“还需读取云端进度”的步骤。未新增系统插件 UI 或进度写入；研究代码仍在 `tools/`，不会进入安装包。

### 新发现

1. 使用下载插件独立会话读取同本书阅读页面，取得 `reader.progress.book` 的完整同条记录：chapterUid、chapterIdx、chapterOffset、progress、summary、updateTime；无需 Agent API Key。没有读取独立 App 会话，也没有调用续期或写入凭据。
2. 云端保存摘要在缓存章节中唯一存在，但其偏移不等于去标签后的文本位置，也不等于已下载 XHTML 的位置。
3. 通过只读正文端点重新取得原始章节 HTML，云端摘要对应的原始 HTML 字符位置与 chapterOffset 相符；字节偏移不符。原始 HTML 与缓存 XHTML 不相同，下载中的图片地址改写会使字符位置移动，因此不能从缓存直接计算上报偏移。
4. 本次样本中，原始 HTML 的 Unicode 字符数和 UTF-16 单位都与云端偏移相符，尚不能区分两种单位。原型同时计算两者；遇到补充平面字符导致坐标不同，不生成通过候选。

### 完整只读链路实测

最终探针对实际已阅读样本完成：系统保存页码 → PDF 当前页文字 → 唯一缓存章节 → 当前登录账号 → 下载清单 checksum/章节指纹 → 云端目录指纹 → 真实 chapterUid/chapterIdx → 原始 HTML 锚点与坐标 → 云端保存摘要的偏移对照。

结果：4 个已导入 PDF 均可读取，1 个当前页有文字，扫描 106 章获得 1 个唯一章节；目录指纹一致、章节身份已核实、原始 HTML 定位成功，候选的 Unicode/UTF-16 坐标一致；云端记录及更新时间存在，保存摘要唯一且原始坐标吻合，`previewMappingReady=true`。一次完整对照使用 10 个受限读取请求；进度/时长写入次数为零。读取前后系统 metadata/content 保持一致。

### 实现与测试

- `read_progress_source.lua` 只允许阅读页面 GET、目录 POST 与 e_0/e_1/e_3 正文读取 POST；进度写接口和其他域名在调用层被拒绝。POST 在这里读取正文/目录，不是上报进度。禁止附带注释数据库缓存写入，Cookie 更新仅保留在本次进程内存。
- `progress_source_map.lua` 保留原始 HTML 标记、实体和空白占用的源坐标，同时建立可见正文锚点映射。未知实体、无法解析的标记、短摘要、重复锚点等不猜测处理。起始页眉跳过候选会定位到实际匹配正文，不虚构之前的位置。
- `saved_progress_probe.lua` 解析带引号/转义/嵌套括号的初始状态，只采纳同一 saved book 记录，不与 currentChapter 混拼。
- `progress_cache_verify.lua` 复用自有缓存 checksum 与目录指纹输入规则，包含真实章节 UID、顺序、标题和版本字段；不能用章节序号代替 UID。
- 本地与设备 LuaJIT 测试覆盖实体、中文、emoji 导致的 UTF-16 差异、源码标记坐标、重复/重叠锚点、错误状态解析、目录顺序变化、独立会话路径，以及写接口/其他域名被拒绝。

### 当前剩余工作

只读映射路线已在一个实际正文位置证明可行。正式 UI/手动同步前，还需合成书在不同字号下的真机矩阵、系统退出/休眠位置落盘时机、其他书籍格式及版本变化处理、原生 EPUB 来源复验。云端更新时间存在不代表已经解决冲突；仍应显示两端位置并由用户明确触发同步。需要为提交前预览、提交后业务确认/读回、账号切换、网络结果不明和云端位置已变化添加状态处理；不能仅凭本次样本开始后台自动同步。

## 插件集成（2026-10-22）

用户确认需求后，进度模块已从研究路径进入插件：只读取已导入书籍的本地/云端百分比；已有书的按钮上传本地位置，新导入的书自动以云端位置恢复本地页码。动作统一为 144×88。新导入时先保存恢复意图；待系统确认/生成 PDF 后，经宿主 LibraryController 原生接口保存位置，再核对持久化结果。失败保留重试状态，不把新书初始 0% 上传。

系统页码百分比是当前排版估算；微信读书记录显示服务端 progress。上传的章节/偏移基于原始 HTML 锚点，和这两个百分比独立。上报百分比按目录字数权重计算，缺少字数时采用已校验缓存的正文长度权重，属于估算。云端记录变化时拒绝覆盖，成功必须有业务确认与章节/偏移读回。当前明确不支持被编辑过的页面映射或无法唯一定位的内容。

隔离 Lua/Qt 行为测试与只读真实账号进度获取均通过。没有为验收向真实账号发送虚构位置，也没有替用户改动现有书的阅读页码。真实新导入恢复与手动上传效果由用户实际使用验收。
