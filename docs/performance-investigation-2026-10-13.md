# 启动与下载性能排查

日期：2026-10-13。源码基线：main `dc47e41`，设备 Qt 6.10.3。
初步排查阶段仅更新 Lua helper 和应用会话脚本。下方“最终代码修复”记录后续构建及部署结果；系统镜像和用户书籍、笔记保留。

## 启动慢：真机计时

原启动会话缺少 HOME/XDG_CACHE_HOME。日志同时出现：

- SDK Qt 6.8 的预编译单元被设备拒绝：`V4 data structure version mismatch. Found 42 expected 48`。
- QML 磁盘缓存读取、保存失败：`No such file or directory`。
- 约 1 MB 的 PinyinLexicon.js 现场编译，从 0.117 秒持续到 18.172 秒。
- Main.qml 和依赖累计编译约 35.940 秒，36.194 秒才开始加载 epaper 显示后端。系统停止阶段约 1–2 秒。

会话脚本现在显式创建并导出 `QML_DISK_CACHE_PATH`。一次缓存生成后，两次复用启动在 18.578 / 18.552 秒开始加载 epaper，缓存保存错误为零，拼音词库加载约 1 ms。

这是显示后端初始化节点，不是完整首屏可操作时间。主页面仍出现缓存依赖 checksum mismatch 并重新编译，不能宣称启动问题全部解决。
下一步优先使用系统匹配 SDK 重编译，而非先拆分整个 Main.qml。[官方 SDK 列表](https://developer.remarkable.com/links)已列出系统 3.28.0.172 对应的 chiappa 5.8.203；仓库当前仍使用旧 5.7.119。

## 启动后进入书页

无点击的受控启动进入书架，并由用户确认。`Main.qml` 默认 `screenName` 为 `shelf`，未发现正常启动自动恢复某本书的路径。

发现另一条确定路径：`downloadStore.onEpubReady` 和 `onOpeningChapterReady` 会进入下载完成的书；其中整本完成回调没有限定用户是否刚请求打开该书。后台下载完成可以切换当前页面。
启动等待期间的误触仍是候选原因，没有重现并记录具体输入事件，不能将两者混为同一个已证实根因。
后续修正应区分“下载”与“下载后打开”，只允许当前明确的打开请求切换阅读页。

## 当前下载：真机探针

现有下载器按章节串行处理。EPUB 正文通常依次获取：阅读网页、e_0、e_1、e_3；CSS 首次另取 e_2，图片另行获取。
一次探针的阅读网页约 765–770 KB，耗时 1.3–1.8 秒；各正文分片约 0.2–0.3 秒。

同一正文章节的受控对比：正常刷新阅读状态 2.743 秒；复用上一章取得的状态 0.724 秒；两次解码 XHTML 完全一致。
探针未写入书籍缓存或阅读进度。这只是一个已登录账号、一本书的单章证据，不是整本提速验收。复用方案需验证状态过期、服务拒绝后的重新获取，以及不同格式书籍。

本次问题书的整本下载已读回为 full、106/106、失败数 0，EPUB 文件存在。本次未部署下载状态复用或并发改动。

结论：官方以批量内容包、异步 Qt 网络和按版本复用的批次缓存减少逐章网页请求；这比“增加并发”更直接解释下载路径的差异。该效率解释是由静态数据流和本项目实测推得，未测官方客户端下载同一本书的时间。默认批次大小、连接复用实际命中率和完整解密契约尚未验证。

完整 REA Evidence 保存在忽略目录 `downloads/official-client/rea-download-evidence.json`。官方二进制和反编译结果不提交 Git。
官方原生接口的认证通道与当前网页 Cookie / Skill API 不同；本轮未向该原生接口发请求，也未实现其解密或认证替换。

## 最终代码修复与真机结果

当前构建改为官方 chiappa SDK 5.8.203 / Qt 6.10.3，与设备一致。官方 SDK 下载路径包含 `3.28.0.172/`；固定 SHA-256 为 `ae0dcec8ff161a90f72b5bbeb77f11c5a14c6c6045c1655584561935994c1832`。支持已有 Docker 流程，也支持已安装 SDK 的 aarch64 Linux 主机直接构建。

构建脚本在清理旧构建目录前检查 SDK Qt 必须为 6.10.3；不兼容 SDK 会拒绝构建并保留旧产物，避免重新引入现场编译问题。

- 空 QML 缓存首次启动：QML ready 2366 ms，Qt 首帧 4957 ms。
- 重复启动：QML ready 2341 ms，Qt 首帧 4903 ms。
- 两次均无预编译版本、依赖校验或缓存保存错误。时间从应用 main 开始计算，AppLoad / 系统切换另计；Qt 首帧不等同于所有墨水屏物理刷新完成。
- 真实 Main/ReaderStore 隔离 `reader-ink` 回归通过，退出恢复系统，Xochitl NRestarts=0。

阅读状态缓存限定为单客户端、同一本书、30 秒。只缓存含有效 psvts 的阅读 HTML，不缓存章节正文；失败不写缓存，章节失败立即失效，原有最多两次的重试会重新请求阅读状态。实例和缓存不跨账号/书籍共用，不落盘。

同一组 8 个真实正文章节：原流程 21.997 秒、45 次请求、9 次阅读网页、8,450,932 网络字节；优化后 12.776 秒、37 次请求、1 次阅读网页、2,282,107 网络字节。正文、CSS、图片文件逐字节一致；耗时降低约 42%，网络读取量降低约 73%。这个比例限于该样本，不承诺所有书籍或网络一致。

独立临时目录的整本下载：106/106 章，失败 0，184 秒，阅读网页 6 次，产物 7,905,074 字节。测试使用占位标题且不附封面，不与用户原 EPUB 的文件哈希直接比较；原书籍、进度和笔记均未替换。临时内容在测试结束后清除。

下载完成回调只更新书架。明确的“打开/阅读”、目录选择和仍处于同一本书的阅读续传可以进入阅读器；页面切换会取消未完成的打开请求。后台下载和恢复队列不再强制切书。
