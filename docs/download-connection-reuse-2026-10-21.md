# 下载连接复用验证

日期：2026-10-21。设备为 Paper Pro Move，系统 3.28.0.172；Qt 界面保持已有封面角标版本。本轮只更新源代码自有的 Lua 下载辅助层，不更新系统、XOVI、AppLoad 或账号数据。

## 修改

`persistent_http.lua` 使用设备已有 `/usr/lib/libcurl.so.4`，每个下载客户端保留一个连接句柄。请求间重置请求选项，同时保留连接、DNS 和 TLS 会话缓存；这是 [curl_easy_reset 的约定](https://curl.se/libcurl/c/curl_easy_reset.html)。不引入并发、不减少图片、不改变 EPUB 内容或章节续传格式。

适配器仅包裹 DownloadManager 的 Client 请求。原客户端继续负责认证头、Set-Cookie 合并、业务错误识别和跨来源重定向。连接不共享到其他下载客户端，旧请求的方法、正文和头部在下次请求前重置；没有启用 curl cookie 引擎。临时替换 LuaSocket 入口后，无论成功或异常都会恢复。

TLS 校验使用系统 CA，要求验证证书与主机名。设备默认 OpenSSL 加密套件清单被阅读站点拒绝；限定为标准 ECDHE/AES-128-GCM 套件后实际 HTTPS 请求成功。未禁用证书校验、未使用弱加密套件。限制为 HTTP/HTTPS，curl 不自动跟随重定向；重定向仍走原客户端的认证隔离逻辑。显式代理或自定义 socket 创建器沿用旧传输。

缺少运行库时，在发送请求前沿用旧客户端；`RM_WEREAD_PERSISTENT_HTTP=0` 也可禁用。已发出的请求失败时不隐式用其他传输重发，继续由原有的有界章节重试和续传机制处理。代码不记录请求凭据、响应内容或书名。

## 真实网络对比

同一组 8 章，均保留正文、CSS 和图片，在内存中逐项比较，不写入用户下载目录。测试仅让注释源缓存写入成为空操作，两种传输完全一致地处理；下载内容未简化。

本样本耗时减少约 65%，约为原速度的 2.9 倍。30 秒阅读状态缓存和正文协议均保留。尝试的最后一轮原方式发生请求失败，未计入耗时或成功样本。不能把这个比例承诺为所有书籍或整本下载的固定提升；长章节、图片大小、打包成本及网络波动仍会影响实际速度。

## 行为验证

- 设备本机虚拟 HTTP 服务：复用单连接、POST 二进制、请求方法/正文/头部隔离、二进制响应、分块编码、多个 Set-Cookie、保留 302/403、服务端关闭后的新连接、截断响应、总超时、sink 失败、异常后恢复原入口，全部通过。
- 原有合成下载续传与阅读状态缓存行为测试通过。
- 实际下载流程在临时目录限制为 8 章：完成 2 章后重建客户端，确认两章从校验缓存恢复且不产生 HTTP 请求；最终 8 章、失败 0、EPUB ZIP 完整性校验通过。该测试不是整本书全章节验收。测试完毕清除临时内容。
- 完整仓库检查、shell 语法及官方 SDK 构建通过。安装后再次通过虚拟 HTTP 服务验证实际安装模块。既有 Qt 界面二进制与本轮更新无关，未重启应用。

## 部署与回退

仅原子更新 `/home/root/weread-qt/helper/lib/persistent_http.lua` 与 `download_manager.lua`，前者先就位，后者随后切换。旧下载器保留为 `download_manager.lua.before-persistent-http`。已在运行的 Lua 下载任务不受影响，新任务启用新传输。

回退可在没有新下载任务启动时，将该备份原子恢复为 `download_manager.lua`；新增模块留在目录中也不会被旧下载器调用。无需修改用户缓存或重启系统。
